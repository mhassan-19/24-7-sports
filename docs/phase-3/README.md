# Phase 3: Android

Status: **approved** (2026-10-23).

## What was built

An Expo SDK 58 app (React Native 0.88, React 19.3, expo-router) in `apps/mobile`, on the same
shared packages as the website: `domain`, `api`, `data` (TanStack Query hooks), `i18n`, `tokens`.
Only the UI layer is new; data, formatting, Egypt time, digits and plural rules are the web's.

| Screen | Route | Notes |
|:--|:--|:--|
| Home | `/` (tab) | Live/today, news, featured competition table and scorers |
| Matches | `/matches` (tab) | Yesterday / today / tomorrow, filter by competition name |
| Competitions | `/competitions` (tab) | Regions, search in list |
| News | `/news` (tab), `/news/:id` | Article body rendered as safe text blocks (no WebView) |
| More | `/more` (tab) | Transfers, Games, Settings |
| Match centre | `/football/match/:id` | Events, lineups (pitch), stats, head to head, news; live polling |
| Competition | `/football/competition/:id` | Same tabs as the web (table with groups, matches, knockout, stats, teams, overview, history), season chips |
| Leaders | `/football/leaders/:id?kind=&season=` | Top scorers / assists |
| Team, Player | `/football/team/:id`, `/football/player/:id` | Matches, squad, stats, photos; stats, career |
| Transfers | `/football/transfers` | Infinite list |
| Search | `/search` (full-screen modal from every top bar) | Debounced 300 ms, grouped results |
| Games | `/games`, `/games/:id` | Guess, prediction, team of the round; device UUID as guest id; answers revealed only after submitting |
| Settings | `/settings` | Theme (dark / light / system); language only when English is enabled; about (version, environment, API host) |

Five bottom tabs (Home, Matches, Competitions, News, More), a top bar with the logomark or back,
search and the theme toggle, pull-to-refresh on every screen, an offline banner, and the shared
query cache persisted to AsyncStorage (cached screens open offline).

## Environments and builds

`EXPO_PUBLIC_*` variables are read at build time. Shell or EAS variables win over `.env.*`.

| Build | API | English | How |
|:--|:--|:--|:--|
| Dev server (`corepack pnpm dev:mobile`) | TEST | on | `.env.development` |
| EAS `development` / `preview` (APK) | TEST | on | `eas.json` |
| EAS `preview-live` (APK) | PROD, read-only (`EXPO_PUBLIC_READ_ONLY`) | on | `eas.json`; the phone test APK |
| EAS `production` (AAB → Play internal track) | PROD | off | `eas.json` |
| Local release APK | as set in the shell; **PROD if nothing is set** | | see below |

The write guard allows writes to PROD only in a production release (`appEnv === 'production'` and
not `__DEV__`). So a local test APK must be built with the TEST variables:

```bash
cd apps/mobile
EXPO_PUBLIC_APP_ENV=test EXPO_PUBLIC_API_BASE_URL=https://testv3.appkora.com/api EXPO_PUBLIC_FEATURE_ENGLISH=true npx expo prebuild --platform android --clean --no-install
cd android
ANDROID_HOME="$LOCALAPPDATA/Android/Sdk" EXPO_PUBLIC_APP_ENV=test EXPO_PUBLIC_API_BASE_URL=https://testv3.appkora.com/api EXPO_PUBLIC_FEATURE_ENGLISH=true ./gradlew app:assembleRelease -PreactNativeArchitectures=x86_64
```

Drop `-PreactNativeArchitectures` for a phone build (all ABIs). Prebuild with the same
`EXPO_PUBLIC_FEATURE_ENGLISH` value as the build: it decides whether the app starts RTL.

### Release signing

- **Recommended:** EAS Build manages the upload keystore (`eas build -p android --profile
  production`) and Google Play App Signing holds the app key. Needs an Expo account and a Play
  Console app.
- **Local:** `plugins/withReleaseSigning.js` adds a release signing config that reads
  `SPORTS247_UPLOAD_STORE_FILE`, `…_STORE_PASSWORD`, `…_KEY_ALIAS`, `…_KEY_PASSWORD` from
  `~/.gradle/gradle.properties` (never the repo). Without them the release build is signed with the
  debug key, which is fine for testing and rejected by Play. `*.jks`, `*.keystore` and
  `credentials.json` are git-ignored.

### Testing on your phone

`builds/24-7-sports-0.1.0-prod-readonly.apk` (≈53 MB, arm64 + x86_64, git-ignored): real PROD
data, read-only (game answers are refused with a message), English switch available. Copy it to
the phone and open it (allow "install unknown apps" for your file manager), or with USB debugging:
`adb install -r builds/24-7-sports-0.1.0-prod-readonly.apk`. Signed with the debug key, so
uninstall it before installing a Play build later.

Rebuild it: prebuild as above, then
`EXPO_PUBLIC_APP_ENV=production EXPO_PUBLIC_API_BASE_URL=https://v3.appkora.com/api EXPO_PUBLIC_FEATURE_ENGLISH=true EXPO_PUBLIC_READ_ONLY=true ./gradlew app:assembleRelease -PreactNativeArchitectures=x86_64,arm64-v8a`
(EAS profile `preview-live`). Gradle doesn't track environment variables: after changing only
them, add `--rerun-tasks` or touch a source file.

## Fixes from website testing (23 Oct 2026)

Found by the product owner on the live Al-Hazm v Al-Feiha match (PROD 18823). The fixes are in
the shared packages, so the website and the app both have them.

| Issue | Cause | Fix |
|:--|:--|:--|
| Live minute missing (row showed "٠د", header nothing) | The API doesn't send the running minute: `matchRoundInfo.time` is the minute the half *started* at, and the match endpoint has no `matchRoundInfo` at all | The clock is computed from when the half started (`created_at`, fixed UTC+3) and ticks every 10 s between polls; the match page takes it from the day list it already polls. "45+2" in added time; no minute at half-time |
| No player photos in the lineup | Photos weren't mapped | Photos on the pitch (shirt number as a badge) and on the bench; the API's shared `no-photo.png` placeholder counts as no photo, so those players keep the number disc / initial |
| Head to head: a row without a score, no dates | The list includes future fixtures (22 Apr 2027) and the match itself; the date wasn't shown | Only past meetings with a score, newest first, each with its date |
| Ratings on players who didn't play | The provider rates unused substitutes (Konate 5.8) and sends 0 for others | Ratings only for starters and substitutes who came on, never 0 |
| (Decided 23 Oct) Kick-off times would be 1 h late from 29 Oct | API dates are a fixed UTC+3 all year (`date` is 3 h ahead of the provider's UTC `time` in January, February and November too); Egypt is UTC+2 in winter | Every API date is converted to Cairo time in one place (`egyptDateTime`), using the time zone database, so DST changes need no code. Verified: 5 Nov 23:00 (API) shows 22:00, 29 Oct 17:35 stays 17:35, on the website and on Android (Hermes) |
| (Found while checking) Postponed matches shown as live | `matchStatus` 3 means postponed ("مؤجل"), not live | New `postponed` state: kick-off time and "مؤجلة", no live dot or polling |

## After approval (23 Oct 2026)

- Match events show newest first (full time on top, kick-off at the bottom) on the website and in
  the app: `newestFirst` in `packages/domain`.
- The app's home screen lists every match of the day, like the website (it stopped at 12).
- Yellow and red cards use their real colours (new `cardYellow`/`cardRed` tokens, outside the
  brand palette by product-owner decision) in events and on the pitch; the app's pitch now shows
  cards too.
- Substituted players carry orange in/out arrows with the minute on the pitch, and the bench shows
  the same arrows for players who came on.
- Player profiles show the photo (shirt number as a badge) when the API has a real one; the big
  number remains for players without a photo.
- In the substitutes list, each player who came on has a smaller line naming the player he
  replaced ("بدلاً من …"). (A starter's own `player_exchanged_name` repeats his name in the API;
  the substitute's entry has the real pair.)
- Substitution events show the player coming on first, larger and in the accent orange
  (`accentText`: Pulse Orange in dark, Orange Ink in light), and the player going off below in
  smaller grey text. The API sends the outgoing player first (`playerOne`).
- Events sit on their team's side (home at the start, as in the match header; away at the end)
  with the minute in the middle; period markers stay centred. Finished matches get "Top events"
  (default: goals, red cards including second yellows, and the shoot-out result when there was
  one) and "All events".

## Changes from the plan

- Search is a full-screen modal opened from every top bar (the web has an inline combobox and a
  sheet); the phone pattern the user asked for on the web.
- The article body is converted to text blocks instead of rendering API HTML in a WebView: no
  script surface and no WebView dependency. Inline images and embeds are not shown yet.
- `react-native-gesture-handler`, `react-native-reanimated` and `react-native-worklets` (optional
  peers of expo-router) are excluded from native linking (`react-native.config.js`): the app
  never imports them, and they made the build slower and hit the Windows path limit.
- Login flows from the Phase 3 brief are out of scope (guest-only v1), so "guest/login" was
  verified as the guest flow: device UUID, one play per day, answers after submit.

## Known gaps

- The app's cached data is keyed by a build id stamped into the app config at build time, so an
  update never shows data cached by an older build (the website does the same).
- Changing language in a release build applies the layout direction after the app is reopened
  (React Native fixes direction at launch; development builds reload by themselves). The settings
  screen says so. Production is Arabic-only, so users never see this.
- No push notifications, deep links from the web, or widgets (not in the v1 plan).
- Article bodies show text only (see above).
